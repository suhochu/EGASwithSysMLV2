# T15 · Functional WB: Golden Path UF의 FN 분해와 입출력 매핑

Golden Path 대상 UF만 FN으로 분해하고 BB와 WB의 입출력 매핑표를 만든다(MAP.md T15 행).

## Before

- T14: UF 7개(`EgasUserFunctions`)가 SYSR 11개를 `satisfy`한다. HARD 0, K15 고아 0, 줄 1554/2600, def 131, Ver 180/180(상한), Common 318/350.
- Fwb는 14줄이다. `CompareTorqueFunction`(FN, 입력 `permissibleTorque`·`actualTorque`, 출력 `excessDetected : Boolean`)과 `l2MonitorWb : TorqueComparisonFunction`의 `compareTorque`뿐이다.
- UF-01의 입력은 `pedalPosition`·`engineSensor`, 출력은 `TorqueExcessFlag`라 현재 FN의 입출력과 맞지 않는다. 입출력 매핑이 필요하다.
- Golden Path는 GP-A(UF-01 TorqueComparison → UF-02 ExcessConfirmation → UF-03 SafeStateEnforcement)와 GP-B(UF-04 PedalSensorFaultDetection → UF-05 LimpHomeTorqueLimit)다(D-03). UF-06·07은 GP 밖이라 분해하지 않는다.

- 제약: 단계별 ms 할당과 WCET은 기능 계층에 두지 않는다. UF에 ASIL·FTTI를 붙이는 것은 T19 범위다. `activeModes`와 limpHome·safeState 진입 조건은 tbd 또는 파일럿 할당이다(D-19).

## AI가 할 일

1. GP-A UF 3개와 GP-B UF 2개를 각각 FN 2~4개로 분해한다(합계 8~12개). 각 UF 안에 FN `action` usage를 두고 FN `action def`는 `in`/`out`으로 입출력을 갖는다. 판정은 파일 단위 keep·merge·demote로 하고 `MIGRATION_MAP.csv`에 기록한다. `CompareTorqueFunction`의 입력 `permissibleTorque`·`actualTorque`는 UF-01 입력(`pedalPosition`·`engineSensor`)에서 FN이 어떻게 만드는지 분해해 맞춘다. 내부 신호가 필요하면 `Common_Signals`에 한 번만 추가한다.
2. FN 입출력은 해당 UF의 입출력을 완전히 덮고, 같은 신호를 두 곳에 정의하지 않는다. FN 사이 연결은 `flow`/`bind`로 쓰고 UF의 `in`/`out`과 FN의 입출력이 모두 연결되도록 한다.
3. BB와 WB의 입출력 매핑표(UF 입출력 → FN 입출력)를 모델 관계 또는 표로 만든다. 모델로 표현되지 않으면 handoff의 표로 대체하고 사유를 기록한다.
4. Lwb의 `allocation`이 깨지지 않게 FN 이름을 유지하거나 Lwb를 최소 수정한다(수정하면 handoff에 쓴다). LC 배치는 T17·T18 범위다.
5. view는 `FunctionalViewpoint`의 기존 view로 FN을 노출하거나 `FwbDecompositionView` 1개만 추가한다. Ver 예산(180)이 가득 찼으므로 추가한다면 예산 조정 또는 정리를 함께 결정하고 handoff에 기록한다.
6. Registry에 FN `action def`·view를 추가한다(`concept-registry-guard`). `python egas2/tools/check_namespace.py`, `lint.py`, `syside check egas2/model` 통과 후 /close-task를 실행한다.
