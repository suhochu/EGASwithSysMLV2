# T07 · 안전 컨셉 1: HARA-lite와 Safety Goal

## 목적

EGAS SZ-01~04에서 시작해 HARA 표와 Safety Goal(SG) 모델을 작성하고, 근거 없는 값은 pilotAssumed 또는 tbd로 표시한다.

## Before

- T06 산출물: `Ctx`의 `EgasSystem`(경계 포트 8개)과 외부 액터 6개, `Common_Signals`의 경계 신호 item 7개, `ContextViewpoint`(D-13).
- T04 사슬의 `EgasArch_Safety_Goal`(`UnintendedAccelerationGoal`: ASIL B(EGAS_e83, standard), FTTI tbd 문자열).
- Common의 `AsilLevel`, `ValueStatusKind`, `SourceRef`, `ValueStatus`, `Catalog_EgasStandard`. `SafetyGoalData` 메타데이터는 DESIGN_MAP 2절에 설계만 있고 `Common_Metadata`에는 아직 없다.
- REF_DIGEST: SZ-01 비의도 가속 ASIL B(e83), SZ-02 가속 부재 QM(e84), SZ-03 비의도 감속 QM(e85), SZ-04 감속 부재 QM(e86). SZ-02~04는 "제어 가능"이라 고려 제외(e88). S/E/C와 FTTI 값은 EGAS에 없다.
- D-04: ISO 26262:2018 용어 사용, EGAS 인용은 SourceRef로 구분. D-05: 범위는 GP-A(SZ-01 L2 토크 감시).

## 읽을 파일

- memory/STATE.md, memory/handoffs/T06.md, 이 카드
- memory/REF_DIGEST.md(SZ와 안전 목표 절), memory/MODELING_RULES.md, memory/REGISTRY.md
- tasks/DESIGN_MAP.md 1절(`Catalog_SafetyTargets`), 2절(`SafetyGoalData`), 3절(Safety 행)
- 레거시는 `legacy_query.py grep "SafetyGoal|Hazard|ftti|asil"`로 요소 위치만 먼저 찾는다. 안전 값을 다루므로 필요한 요소만 `show`한다.

## 설계 입력

- Safety 계층 예산은 130줄이다(현재 29줄).
- HARA는 SZ-01~04 4행으로 시작한다. S/E/C는 EGAS에 값이 없으므로 `pilotAssumed` 또는 `tbd`로 표시하고 근거(rationale)를 비우지 않는다. ASIL은 EGAS가 준 값만 `standard`다. SZ-02~04의 "고려 제외"(e88)는 모델에서 제외 사유로 남기고 SG로 만들지 않는다.
- SG는 `UnintendedAccelerationGoal` 하나로 시작하고 FTTI는 `Catalog_SafetyTargets`(DESIGN_MAP 1절)로 옮겨 tbd 상태로 참조한다. 새 수치를 만들지 않는다.
- 위험 사건의 입력·출력은 T06 경계 신호·액터(예: `AccelerationPedalPosition`, `TorqueInterventionRequest`, `FuelIgnitionCommand`)를 참조하며 중복 정의하지 않는다.
- viewpoint는 `SafetyConceptViewpoint`(위험 → ASIL → SG 추적)이고 view는 `HaraTable`, `SafetyGoalView`다.

## AI가 할 일

1. `concept-registry-guard`로 HARA 행·SG·`SafetyGoalData`·`Catalog_SafetyTargets`·`SafetyConceptViewpoint`를 Registry에 먼저 등록한다. `egas-ref-lookup`으로 EGAS 문단 ID를 찾아 SourceRef를 만든다.
2. `Common_Metadata`에 `SafetyGoalData`(asil, severity, exposure, controllability, hazardousEvent, ftti, safeState)를 추가한다. 형식은 T02 결정(`COMMON_METADATA_DECISION.md`)을 따른다.
3. `Catalog_SafetyTargets`를 새 공통 package로 만든다(SG별 ASIL·FTTI, status 필수, FTTI는 tbd). 하드웨어 지표 목표는 T19에서 채우므로 여기서는 넣지 않는다.
4. `EgasArch_Safety_Goal`을 확장한다: HARA 표(SZ-01~04, 위험 사건, S/E/C, ASIL, 제외 사유), `UnintendedAccelerationGoal`의 `SafetyGoalData`와 safeState.
5. `SafetyConceptViewpoint` 1개와 `HaraTable`, `SafetyGoalView`를 `EgasArch_Ver_Views.sysml`에 추가한다. Syside가 표 뷰를 렌더하지 않으면 GeneralView로 대체하고 EVALLOG에 적는다.
6. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
7. 레거시 안전 관련 요소의 처분은 `legacy-distiller` 기준으로 MIGRATION_MAP에 기록한다. 일부만 처리했으면 `*` 행은 바꾸지 않는다.
