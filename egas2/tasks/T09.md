## 설계 입력

- Val 예산은 80줄이다(현재 11줄). verification def는 SHR당 1개(병합 가능), 수용 기준은 `doc`와 tbd 값 참조로만 쓴다. 절차 단계·테스트 스크립트는 쓰지 않는다.
- 수치(허용 오차, 응답 시간)는 Common에만 둔다. 카탈로그에 항목이 없으면 `@ValueStatus` tbd로 두고 추가하지 않는다(Common 264/250, OI-08/09). 꼭 필요하면 사용자에게 묻는다.
- 안전 값(ASIL, FTTI)은 SG를 참조하고 다시 쓰지 않는다. `AuditIso26262AsilDCompliance`의 ASIL-D 문구는 가져오지 않는다.
- 검증 방법 종류(test·analysis·inspection·demonstration)는 verification def의 `doc`와 기존 메타데이터 범위에서 처리한다. 새 메타데이터는 만들지 않는다.
- viewpoint는 `RequirementViewpoint`를 재사용하고 view는 `ValidationCoverageMatrix`(GridView) 1개를 추가한다. 렌더가 안 되면 GeneralView 대체를 EVALLOG에 적는다.

1. `concept-registry-guard`로 새 verification def와 `ValidationCoverageMatrix`를 Registry에 먼저 등록한다. `MonitorTorqueValidation`은 확장한다.
2. 레거시 21개를 keep·merge·demote·delete로 판정한 표를 만들어 사용자에게 보여준다(GATE).
3. `EgasArch_Val_Validation.sysml`에 승인된 verification def만 작성한다. 각각 `verify`로 SHR을 가리키고 `@SourceRef`, 필요한 `@ValueStatus`를 붙인다.
4. `ValidationCoverageMatrix`를 `EgasArch_Ver_Views.sysml`에 추가한다.
5. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
