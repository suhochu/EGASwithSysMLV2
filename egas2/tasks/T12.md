# T12 · System Requirements와 FSR

## 목적

시나리오(T10)와 거동(T11)에서 SYSR 20개 이하를 파생하고, 안전 SYSR(FSR)에 SG의 ASIL을 상속한다(MAP.md T12 행). 레거시 `6`(요구 16개, 1,793줄)에서 파일럿 범위(D-05)에 필요한 것만 이주한다.

## Before

- Sysr(18줄)에는 `TorqueComparisonRequirement` 1개와 SHR·`l2Behavior`로의 `#derivation` 2개뿐이다(GP-A 사슬).
- T11: `EgasBehavior`(상태 5·전이 6), 액션 3, `OperatingMode`. 전이 조건·limp home 제한 값·개입 감소량·확정 시간은 tbd다. `toLimpHome`의 센서 이중 채널 고장 조건은 아직 SYSR로 정해지지 않았다.
- Safety: SG-01의 ASIL은 `sg01Asil`(pilotAssumed·tbd 상태는 카탈로그 참조), FTTI는 tbd, safeState `TorqueLimited`는 pilotAssumed다. 안전 값 승인 절은 비어 있다(OI-07).
- Common 270/250(OI-08). `SafetyRequirementData` 메타데이터(DESIGN_MAP 3절)는 아직 없다. OI-09(tbd 값 3개)·OI-10(limp home 제한 값)이 이 Task에서 정해져야 한다.
- 레거시 6은 `*` 행이 unmapped이다.

## AI가 할 일

1. `concept-registry-guard`로 새 SYSR·FSR, `SystemRequirementViewpoint`, view를 Registry에 먼저 등록한다. `TorqueComparisonRequirement`는 유지하고 중복을 만들지 않는다.
2. 레거시 `6`의 요구 16개를 keep·merge·demote·delete로 판정한 표를 만들어 사용자에게 보여준다(GATE).
3. SHR·시나리오·거동(`EgasBehavior`, `LimitTorque`, `ReduceTorque`, `ArbitrateTorque`)에서 SYSR을 20개 이하로 파생해 `#derivation`으로 연결한다. 조건·한계 값은 복사하지 않고 tbd로 둔다.
4. 안전 SYSR은 FSR로 표시하고 SG-01에서 ASIL을 상속한다(`iso26262-concept-assistant`로 검증, asilOrigin 기록). ASIL 분해는 하지 않는다. 근거는 `egas-ref-lookup`으로 SourceRef를 만든다.
5. `SafetyRequirementData`가 필요하면 Common 예산 영향(OI-08)을 사용자에게 알리고 Common 추가 또는 Sysr 안에서의 대체를 묻는다. OI-09·OI-10의 tbd 값은 필요한 것만 카탈로그에 추가하거나 tbd로 남긴다.
6. `SystemRequirementViewpoint`와 SYSR 표·추적 view(`SysrTable`, `FsrView` 중 필요한 것)를 `EgasArch_Ver_Views.sysml`에 추가한다. 렌더가 안 되면 GeneralView 대체를 EVALLOG에 적는다.
7. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
8. 처리를 끝낸 레거시 `6`은 MIGRATION_MAP의 `*` 행을 갱신하고 강등분은 `archive/`에 의도만 남긴다.

## GATE

- 레거시 `6` 판정표와 FSR 목록은 사용자가 확인한다.
- 안전 값(S/E/C, FTTI, safeState, ASIL 상속 결과) 승인이나 `reviewed` 표시는 AI가 하지 않는다. 값이 필요하면 pilotAssumed 또는 tbd로 두고 사용자가 승인 절에 기록한다(OI-07).
- Common 예산 초과(OI-08)가 더 커지는 추가는 사용자에게 먼저 묻는다.
