# T11 · System Behavior(구조·연산·거동)

## 목적

레거시 `5-1`(액션 22개, 700줄)과 `5-2`(상태 7개, 482줄)를 상태머신 1개, 모드 개념 1종, 연산·정보구조 최소 모델로 줄여 Beh에 둔다(MAP.md T11 행). T10 시나리오의 선·후조건이 거동 상태와 이어지게 한다.

## Before

- Beh(16줄)에는 `L2MonitorBehavior`(monitoring → excessSuspected → safeState)와 `l2Behavior`, `MonitorTorqueRequirement`로의 `#refinement` 하나뿐이다.
- T10: Scn 시나리오 6개(main 2: `L2TorqueMonitorScenario`, `DriverTorqueDemandScenario`. alternative 3. exception 1: `PvsFaultLimpHomeScenario`). 선·후조건은 `@ScenarioData`의 문자열이다.
- limp home의 제한 값은 tbd이고 모드 개념(정상·개입·limp home·safe state)을 담은 상태 정의가 없다. `SafeStateStage` enum은 Common에 있다.
- 레거시 5-1·5-2는 `*` 행이 unmapped이다.

## 읽을 파일

- memory/STATE.md, memory/handoffs/T10.md, 이 카드
- memory/MODELING_RULES.md, memory/REGISTRY.md, tasks/DESIGN_MAP.md 3절(Behavior 행: `BehaviorViewpoint`)
- 레거시는 `legacy_query.py list`로 5-1, 5-2 목록만 조회하고 필요한 요소만 `show`한다. 후보: 5-2의 `EgasBehavior`, `DrivingControlRegion`, `EmergencyInterventionRegion`, `SafetyMonitoringRegion`. 5-1의 `ArbitrateTorqueDemand`, `ExecuteEmergencyFailSafe`, `ManageHardwareFailSafe`, `TorqueDemand`.

## 설계 입력

- Beh 예산은 200줄이다(현재 16줄). 상태머신은 `EgasBehavior` 1개로 통합하고 모드는 그 안의 상태 또는 기존 `SafeStateStage`를 참조하는 방식 1종으로 정한다. 모드 enum을 새로 만들면 Common 예산(264/250, OI-08)에 영향을 주므로 Beh 안에서 해결하거나 사용자에게 묻는다.
- Beh에는 거동 요구(상태·전이·동작)만 둔다. 컴포넌트·포트·블록은 쓰지 않는다(SPES 점검: `spes-viewpoint-guard`).
- 전이 조건과 한계 값(limp home 토크, 디바운스, 허용 편차)은 복사하지 않고 tbd로 둔다. 안전 값은 SG를 참조한다.
- CalibrationHandling, DiagnosticsHandling, 크루즈, 과열 관련 상태는 D-05 범위 밖이므로 강등한다.

## AI가 할 일

1. `concept-registry-guard`로 새 상태·액션·`BehaviorViewpoint`와 view를 Registry에 먼저 등록한다. `L2MonitorBehavior`는 확장 또는 `EgasBehavior`로 병합한다.
2. 레거시 5-2 상태 7개와 5-1 액션 22개를 keep·merge·demote·delete로 판정한 표를 만들어 사용자에게 보여준다(GATE).
3. `EgasArch_Beh_Behavior.sysml`에 상태머신 1개(정상, 개입, limp home, safe state 중 시나리오가 쓰는 것)와 전이를 쓰고 `#refinement`로 SHR·시나리오와 연결한다.
4. 필요한 정보구조는 item def 1~2개로 줄이고 신호는 Ctx의 경계 신호를 재사용한다(중복 정의 금지).
5. `BehaviorViewpoint`와 `StateView`(또는 대체)를 `EgasArch_Ver_Views.sysml`에 추가한다. 렌더가 안 되면 GeneralView 대체를 EVALLOG에 적는다.
6. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
7. 처리를 끝낸 레거시 파일은 MIGRATION_MAP의 `*` 행을 갱신하고 강등분은 `archive/`에 의도만 남긴다.
