# T10 · 운용 시나리오

## 목적

5개 내외의 main·alternative·exception 시나리오로 목표 충족 관계와 선·후조건을 정리한다(MAP.md T10 행). 레거시 `4-1`(use case 6개, 1,663줄)에서 파일럿 범위(D-05)에 필요한 것만 이주한다.

## Before

- 현재 Scn(57줄)에는 `L2TorqueMonitorScenario`(main, GP-A)와 T08이 추가한 `BrakeOverrideScenario`·`TorqueInterventionScenario`·`SafetyAssessmentScenario`(alternative, D-15)가 있고 각각 SHR을 `#refinement`로 연결한다.
- GP-B(PVS 이중 채널 고장 → limp home, EGAS 11.1.1)를 다루는 시나리오가 없다. exception 종류도 없다.
- soft SHR 2개(`SteadyStatePrecisionRequirement`, `PedalResponseRequirement`)를 refine하는 시나리오가 없다(L7 비대상, 필수 아님).
- T09: SHR 6개 모두 verification이 있고 `validationCoverageMatrix`가 있다. Val은 75/80줄이다.

## 읽을 파일

- memory/STATE.md, memory/handoffs/T09.md, 이 카드
- memory/MODELING_RULES.md, memory/REGISTRY.md, tasks/DESIGN_MAP.md 3절(Scn 행: `ScenarioViewpoint`, `GoalScenarioMatrix`)
- 레거시는 `legacy_query.py list "01. Requirements Viewpoint/4-1. Scenario Model Usecase.sysml"`로 목록만 조회하고 필요한 요소만 `show`한다. 후보: `Hardware Fail-safe`(GP-B), `Driving Torque Demand Arbitration & Control`, `Emergency Intervention`. 나머지 3개(Calibration, Diagnostics, Architecture Review)는 D-05 범위 밖이다.

## AI가 할 일

1. `concept-registry-guard`로 새 시나리오와 `GoalScenarioMatrix`를 Registry에 먼저 등록한다.
2. 레거시 use case 6개와 현재 Scn 4개를 keep·merge·demote·delete로 판정한 표를 만들어 사용자에게 보여준다(GATE).
3. GP-B를 exception 시나리오 1개로 추가한다(PVS 이중 채널 고장, limp home). 선·후조건은 `@ScenarioData`와 `doc`으로만 쓰고 절차 단계·시퀀스는 쓰지 않는다. 목표(Objective)와 SHR에 대한 `#refinement` 관계를 건다.
4. 필요하면 main 하나(예: 운전자 토크 요구)와 soft SHR을 refine하는 시나리오를 추가하되 합계 5개 안팎을 넘기지 않는다.
5. `ScenarioViewpoint`와 `GoalScenarioMatrix`(GridView)를 `EgasArch_Ver_Views.sysml`에 추가한다. 렌더가 안 되면 GeneralView 대체를 EVALLOG에 적는다.
6. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
7. `4-1`의 처리를 끝내면 MIGRATION_MAP의 `*` 행을 갱신하고 강등분은 `archive/`에 의도만 남긴다.
