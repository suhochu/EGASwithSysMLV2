# T08 · 이해관계자 요구(SHR)

## 목적

레거시 SHR 23개(`3-2`, 630줄)를 hard goal 12개 이하로 통합하고, 경계 값만 참조하며, 각 SHR이 T07의 `UnintendedAccelerationGoal` 또는 Concern에 연결되도록 한다.

## Before

- T07 산출물: `EgasArch_Safety_Goal`의 `UnintendedAccelerationGoal`(ASIL B standard e83, FTTI tbd, safeState `TorqueLimited` pilotAssumed), HARA 4행, `Catalog_SafetyTargets`, `SafetyGoalData`.
- T05 산출물: `Needs`의 이해관계자 3개, Concern 6개, `Obj` 목표 2개(`SafeTorqueObjective` hard, `ResponsiveTorqueObjective` soft). T06 산출물: 경계 신호 7개(`Common_Signals`).
- T04 사슬의 `EgasArch_Shr_Requirement`(`MonitorTorqueRequirement :> UnintendedAccelerationGoal`, `GoalData` hard AND).
- D-02: SHR은 hard goal의 하위 유형으로 모델링. D-05: 범위는 GP-A(SZ-01 L2 토크 감시)와 L3 Q&A. OI-07: S/E/C·safeState는 미승인이므로 SHR이 이 값을 확정처럼 인용하지 않는다.

- memory/MODELING_RULES.md, memory/REGISTRY.md, memory/REF_DIGEST.md(EGAS 요구 문단)

## 설계 입력

- Shr 예산은 160줄이다(현재 14줄). hard goal은 12개 이하다. 하위 SHR(`SHR-02-1` 등)은 부모에 흡수하거나 강등한다.
- D-05 범위 밖(캘리브레이션 SHR-05, 진단·정비 SHR-06, 크루즈 SHR-10, 과열 SHR-09)은 `legacy-distiller` 기준으로 강등·폐기를 판정하고 MIGRATION_MAP에 파일·그룹 행으로 기록한다.
- 수치(허용 토크 편차, 응답 시간 등)는 Common 카탈로그에만 둔다. 레거시 SHR 본문에 수치가 있으면 Shr에 복사하지 않고 `@ValueStatus`와 함께 카탈로그를 참조하거나 tbd로 둔다.
- 각 SHR은 `UnintendedAccelerationGoal` 또는 Concern을 `frame`·specialize로 연결한다. SG의 ASIL은 SHR에서 다시 쓰지 않고 SG를 참조한다.
- viewpoint·view는 `RequirementViewpoint`(있으면 재사용)와 `ShrTable`이다. Syside가 표 뷰를 렌더하지 않으면 GeneralView로 대체하고 EVALLOG에 적는다.

## AI가 할 일

1. `concept-registry-guard`로 새 SHR requirement def와 `ShrTable`을 Registry에 먼저 등록한다. 기존 `MonitorTorqueRequirement`는 병합 후보로 먼저 검토한다.
2. 레거시 SHR 23개를 keep·merge·demote·delete로 판정한 표를 만들고 사용자에게 보여준다(GATE).
3. `EgasArch_Shr_Requirement.sysml`에 승인된 SHR만 작성한다. 각 SHR에 `@GoalData`, `@SourceRef`, 필요한 `@ValueStatus`를 붙인다(`egas-ref-lookup`으로 EGAS 문단 ID 확인).
4. `ShrTable` 뷰를 `EgasArch_Ver_Views.sysml`에 추가한다.
5. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
6. 처리를 끝낸 레거시 파일은 MIGRATION_MAP의 `*` 행 disposition을 갱신한다. 일부만 처리했으면 바꾸지 않는다.
