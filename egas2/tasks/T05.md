# T05 · 목적, 이해관계자, Concern(Needs)을 정리한다

## 목적

목적, 이해관계자, Concern(Needs)을 정리한다. 레거시를 고도 규칙으로 걸러 이주하고 Goal 구조(hard/soft, AND/OR)를 작성한다.

## Before

- T04 사슬(Obj `SafeTorqueObjective`, Needs `UnintendedAccelerationConcern`), `lint.py`, Syside 검증 구문 표(`MODELING_RULES.md`), Pilot Gate 0 결과(T04 handoff).
- D-05 범위: 가솔린 매니폴드 분사, 토크 비교 감시, L3 Q&A. 그 밖의 변형은 범위 밖이다.

## 읽을 파일

- memory/STATE.md, memory/handoffs/T04.md, 이 카드
- memory/MODELING_RULES.md, memory/OPEN_ISSUES.md(OI-04), memory/REGISTRY.md
- 레거시는 `legacy_query.py list|show`로 `1. Objectives.sysml`(56줄), `3-1. GoalModel Stakeholders and Concerns.sysml`(약 420줄)의 요소 목록만 먼저 조회하고 필요한 요소만 `show`한다.

## 설계 입력

- DESIGN_MAP 3절: GoalViewpoint(목표 완전성, Hint 4-2), GoalTreeView(AND/OR 트리), StakeholderConcernMatrix(이해관계자×Concern 표).
- 목표는 `GoalData`(kind hard·soft, refinement AND·OR) 메타데이터를 요소 본문 안에 둔다. 충돌·기여 관계는 문서 주석이 아니라 모델 관계로 쓸 수 있는지 Syside로 확인하고, 안 되면 대체안을 `MODELING_RULES.md`에 기록한다.
- Obj는 목표 12개 이하, Needs는 이해관계자와 Concern을 합쳐 계층 예산(120줄) 이내. 안전 관련 목표(SG)는 T07에서 다루므로 여기서는 Concern까지만 둔다.
- 레거시 판정은 `legacy-distiller` 기준(keep·merge·demote·delete·rebuild)을 따르고 MIGRATION_MAP에 기록한다.

## AI가 할 일

1. `concept-registry-guard`로 새 개념(목표, 이해관계자, Concern)을 Registry에 먼저 등록한다.
2. 레거시 두 파일의 요소를 판정하고 이주한다. T04 사슬의 `SafeTorqueObjective`와 `UnintendedAccelerationConcern`은 유지하고 새 요소와 연결한다.
3. Obj의 목표 구조(hard/soft, AND/OR)와 Needs의 이해관계자·Concern을 작성한다. 근거가 있는 항목은 `@SourceRef`와 `@ValueStatus`를 붙인다(`egas-ref-lookup`).
4. GoalViewpoint와 GoalTreeView, StakeholderConcernMatrix를 작성한다. Syside가 표 뷰를 렌더하지 않으면 GeneralView 또는 표 텍스트로 대체하고 EVALLOG에 적는다.
5. OI-04를 처리한다: Common의 `Catalog_EgasStandard`와 `Units`의 메타데이터를 속성 본문 안으로 옮기고 Syside로 부착 위치를 확인한다.
6. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행한다.
7. 레거시 처리를 끝낸 파일은 MIGRATION_MAP의 `*` 행 disposition을 갱신한다.
