1. 레거시 기능 요소 목록과 SYSR 11개를 보고 UF를 5~7개로 도출한다. 후보: `TorqueComparison`(GP-A), `ExcessConfirmation`·`SafeStateEnforcement`, `PedalSensorFaultDetection`·`LimpHomeTorqueLimit`(GP-B), `TorqueArbitration`(우선순위·브레이크 오버라이드·개입), `PedalOutputResponse`. 판정은 파일 단위 keep·merge·demote로 하고 `MIGRATION_MAP.csv`에 기록한다. UF 경계는 시스템 경계에서 관측 가능한 기능이다(OI-03: `L2MonitorFunction`을 재분류).
2. UF마다 `action def`와 `in`/`out` 매개변수를 쓴다. 입출력은 Ctx 경계 신호의 부분집합이고, 내부 신호가 필요하면 `Common_Signals`에 한 번만 추가한다(OI-06). 같은 신호를 두 곳에 정의하지 않는다.
3. SYSR 11개를 각각 UF가 `satisfy requirement`로 만족하게 한다(OI-11 해소, K15 고아 0). 한 UF가 여러 SYSR을 만족해도 된다.
4. 모드 의존을 UF mode channel로 표현한다. Beh `EgasBehavior`의 모드 상태와 Common `OperatingMode`를 재사용하고 새 모드 개념은 만들지 않는다(D-16).
5. `FunctionalViewpoint`(Ver)와 view 3개(UfHierarchyView, ModeDependencyView, UfInterfaceTable)를 정의한다. 렌더되지 않으면 표·텍스트로 대체하고 사유를 기록한다.
6. 사용자가 T14에 흡수하라고 한 Gate-R 항목 R3~R5를 처리한다(상세는 `memory/handoffs/GateR_T13.md` 7절, OI-12~14). 필요한 수정은 이 카드 범위 안에서만 하고 고친 내용은 handoff에 쓴다.
   - R3(OI-12): `HardwareFailureConcern`을 SHR이 `frame`하게 하거나 사슬에서 정리한다. `toLimpHome`의 고장 조건은 근거가 없으면 tbd로 표시한다. SG→SYSR 문자열 관계는 UF의 `satisfy`로 보완하고 모델 관계로 바꿀 수 있으면 바꾼다.
   - R4(OI-13): `TorqueMonitorPort`의 의도(내부 포트 여부)를 정해 액터·connect를 채우거나 내부 포트로 표시한다.
   - R5(OI-14): 누락 view(OperationalFlowView, InfoStructureView, SYSR TraceView)를 정의하고 `scenarioView`를 `ScenarioViewpoint`에 묶는다. 시나리오 3개의 OBJ refine 누락은 `ScenarioViewpoint` 설명을 "SHR 기준"으로 맞추거나 refine을 추가한다.
