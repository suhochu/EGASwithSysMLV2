## 설계 입력

- 접두사: `EgasArch_`; 계층 순서는 Common → Obj → Needs → Ctx → Safety → Shr → Val → Scn → Beh → Sysr → Fbb → Fwb → Lbb → Lwb → Ver. 상위 계층의 하위 import와 순환 import를 금지한다.
- 블랙박스 순도: `EgasSystem`, `LogicalEgasSystem`에는 port와 doc만 허용한다. `part`, `perform`, `action`, `state`, `exhibit`, `assert`는 금지한다.
- SPES Hint 검사: 컨텍스트 액터와 시나리오 액터 양방향 일치; 모든 목표와 시나리오가 서로 하나 이상 연결; 시나리오에 선·후조건; 요구 속성이 목표 하나 이상으로 추적; 입력·출력 일관성.
- 관계 규칙을 정한다: `refine`, `derive`, `satisfy`, `allocate`의 허용 주체·대상·방향. `satisfy`는 L10 이상 설계 요소가 요구를 만족할 때만 허용한다.
- 현재 `kpi_config.json`의 `registry_enforced`는 false. 기존 Registry 정의와 4개 Common 패키지를 대상으로 점검이 통과한 뒤 true로 전환한다.
- MAP 목적의 구현은 모델링 규칙, 관계·추적 검사, `egas2/tools/lint.py`, Registry enforcement, `spes-viewpoint-guard` skill이다.

## AI가 할 일

1. `concept-registry-guard`, `sysml-v2-modeling-style`, `lint-triage` skill을 적용하고 Registry의 개념명·동의어·상태를 점검한다.
2. SPES Hint와 EGAS2 계층·BB 규칙을 machine-checkable 규칙과 명확한 진단 메시지로 정리한다.
3. 관계 구문별 허용 주체·대상·계층 방향 및 추적 검사 규칙을 결정하고 짧은 모델링 규칙 문서에 기록한다.
4. `egas2/tools/lint.py`와 pass/fail fixture 테스트를 작성한다. 네임스페이스, Registry 등록·중복, import 방향·cycle, satisfy 방향, BB 순도, Hint 추적 누락을 검사한다.
5. 기존 네 Common 모델에서 lint를 실행해 결과를 검토하고, 통과할 때 `registry_enforced`를 true로 바꾼다.
6. `.github/skills/spes-viewpoint-guard/SKILL.md`를 작성한다.
