# T06 · 시스템 컨텍스트: 블랙박스 경계, 외부 액터, 인터페이스

시스템 컨텍스트: 블랙박스 경계, 외부 액터, 인터페이스. `EgasSystem`을 포트만 남기고 정리하고, 액터·인터페이스를 이주하며, 내부 신호를 기능 계층 후보로 분류하고 Item definition을 요약한다.

## 설계 입력

- DESIGN_MAP 1절 `Common_Signals`: 경계 신호(페달 PVS1·PVS2, 브레이크, 엔진 속도, 토크 요청 등)를 T06에서 추가한다. 같은 신호를 두 곳에서 정의하지 않는다. 내부 신호는 T14에서 추가하므로 여기서는 분류만 한다.
- DESIGN_MAP 3절: ContextViewpoint(입출력·액터 완전성, Hint 4-1), ContextView(인터커넥션: 경계와 외부 액터), ActorInterfaceTable(인터페이스 표).
- Ctx는 L6에 따라 블랙박스다: 포트와 doc만 두고 내부 part·action·state를 두지 않는다. 예산은 180줄이다.
- 외부 액터는 Needs의 이해관계자와 구분한다. 이해관계자(`Driver`)는 사람의 관심사이고 액터는 경계 밖에서 신호를 주고받는 대상이다. 둘의 연결은 doc 문장이 아니라 모델 관계로 쓸 수 있는지 Syside로 확인하고, 안 되면 대체안을 `MODELING_RULES.md`에 기록한다.
- 레거시 액터 14개 중 D-05 범위와 GP-A(SZ-01 L2 토크 감시)에 필요한 것만 남긴다. 레거시 판정은 `legacy-distiller` 기준(keep·merge·demote·delete·rebuild)을 따르고 MIGRATION_MAP에 기록한다.

## AI가 할 일

1. `concept-registry-guard`로 새 액터, 신호 item, 포트, `ContextViewpoint`를 Registry에 먼저 등록한다.
2. `EgasArch_Ctx_Context.sysml`을 정리한다: `EgasSystem`은 포트와 doc만 유지하고 `TorqueMonitorPort`는 그대로 둔다. 외부 액터 part def와 포트를 추가한다.
3. 경계 신호 item(액셀 페달 PVS1·PVS2, 브레이크, 엔진 속도, 토크 요청 등)을 `EgasArch_Common_Signals`에 추가한다(새 공통 package이므로 Registry 등록 후 작성). 값이 필요하면 `@SourceRef`와 `@ValueStatus`를 붙이고 수치는 Common 카탈로그에만 둔다(`egas-ref-lookup`).
4. 레거시 내부 신호·item을 "경계 신호 / 기능 계층 후보(T14)"로 분류한 표를 `memory/handoffs/T06.md`에 남긴다. 후보는 모델에 넣지 않는다.
5. OI-05를 처리한다: Concern의 `subject`와 Ctx의 `EgasSystem`을 연결하는 방법을 정하고(하위 계층 import 규칙을 어기지 않는 선에서) 결정을 `DECISIONS.md`에 기록한다. 규칙상 불가능하면 대체안을 `MODELING_RULES.md`에 쓴다.
6. `ContextViewpoint` 1개와 `ContextView`, `ActorInterfaceTable`을 `EgasArch_Ver_Views.sysml`에 추가한다. Syside가 표 뷰를 렌더하지 않으면 GeneralView로 대체하고 EVALLOG에 적는다.
7. 파일마다 `check_namespace.py`, `lint.py`, `syside check egas2/model`을 실행하고 IDE 진단은 사용자에게 확인한다.
8. 레거시 세 파일 중 처리를 끝낸 파일은 MIGRATION_MAP의 `*` 행 disposition을 갱신한다. 일부만 처리했으면 바꾸지 않는다.
