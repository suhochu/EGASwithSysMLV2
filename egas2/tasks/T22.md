# T22 · 추상화 계층 시연 (선택)

## 목적

L2 감시 컴포넌트(`l2Monitor`)를 새 SUD(system under design)로 보고 요구 → 기능 → 논리를 얇게 한 번 더 돈다(MAP.md T22 행, SPES 3.4.1: 컴포넌트를 분해하면 각 컴포넌트가 다음 계층의 새 SUD가 되고 같은 산출물 세트가 반복된다). MAP과 다른 점은 없다. T21b가 T22를 건너뛰기로 했으나 사용자가 T23 앞에 실행하기로 했다. 새 레거시 이주는 없다.

## Before

- SUD 후보 `l2Monitor`(`L2MonitorComponent`, Lwb 84~104행): UF-01 `torqueComparison`, UF-02 `excessConfirmation`, FN-01~05(`derivePermissibleTorque`, `estimateActualTorque`, `compareTorque`, `confirmExcessPersistence`, `issueSafeStateRequest`)를 할당받고 FSR `sysrTorqueComparison`·`sysrExcessConfirmation`을 `satisfy`한다. 포트: `accelerationInput`, `sensorInput`, `torqueMonitor`, `safeStateRequestOut`.
- 계층 토큰은 고정이라(Obj~Ver) 새 계층 토큰을 만들 수 없다. 새 요소는 기존 토큰의 새 파일에 둔다. 상위 계층은 하위를 import하지 않으므로 Fbb에서 Fwb의 FN을 참조할 수 없다.
- 예산 현재: Sysr 306/320, Fwb 156/170, Lwb 231/250, Ver 284/300, Common 407/410. 상주 컨텍스트 약 18.7KB(한도 20KB)라 카드·보고서는 짧게 쓴다. 안전 값 pilotAssumed 33·tbd 2·reviewed 0.
- `AbstractionLayer`(Common_Metadata, `layer : Integer`)는 정의만 있고 쓰인 곳이 없다.

## 읽을 파일

- memory/STATE.md, memory/handoffs/T21b.md, 이 카드
- 모델은 이름 검색으로만: Sysr(`TorqueComparisonRequirement`, `ExcessConfirmationRequirement`와 `#derivation` 구문), Lwb(`L2MonitorComponent`, `allocation fn01..fn05`, `satisfy`), Fwb(`torqueComparisonWb`, `excessConfirmationWb`)

## AI가 할 일

1. **설계안을 표로 만들어 모델에 쓰기 전에 사용자에게 보인다(GATE).** 항목: 새 요구 2개의 이름·문장, 기능 계층 처리(아래 3번), 하위 LC 3개의 이름·FN 할당, 새 파일·예산 변화, 새 D-xx 필요 여부.
2. 요구: `EgasArch_Sysr_L2Monitor`(`01_Requirements/`)에 SUD 수준 요구 2개를 둔다. `sysrTorqueComparison`에서 파생(비교 판정), `sysrExcessConfirmation`에서 파생(초과 확정). `@SafetyRequirementData`(level은 Common_Enums에서 TSR 존재 여부 확인), `@AbstractionLayer { layer = 1; }`, `@SourceRef`, `@ValueStatus`(pilotAssumed). ASIL은 `sg01Asil` 상속이고 새 수치는 만들지 않는다. 문장은 영어, 시간·한계 값은 기존 카탈로그를 참조하거나 tbd로 인용만 한다.
3. 기능: FN-01~05가 이미 SUD의 기능 분해(UF-01·02 아래)다. 새 `Fbb`·`Fwb` 파일은 만들지 않고 요구 파일·논리 파일의 doc과 `@AbstractionLayer`로 "SUD의 BB는 상위 WB 재사용"임을 적는다. 만들어야 한다고 판단되면 설계안 표에 이유를 쓰고 사용자가 정한다(D-32 후보).
4. 논리: `EgasArch_Lwb_L2Monitor`(`03_Logical/`)에 `part def L2MonitorSudComponent :> L2MonitorComponent`와 하위 part 3개(예: `permissibleTorqueUnit`=FN-01, `actualTorqueUnit`=FN-02, `excessJudgeUnit`=FN-03~05)를 둔다. 상위 포트는 `bind`로 하위에 위임하고 하위 연결은 `connect`로 쓴다. `allocation`(FN → 하위 LC)과 `satisfy`(새 요구 → 하위 LC)를 쓴다. 하위 LC는 `AsilAllocatedComponent`를 상속하고 ASIL B inherited, 분해 없음. 독립성·FFI·FIT·DC는 모델링하지 않는다(한계로 기록).
5. 뷰: `Ver_Views`에 view 1개(`l2MonitorSudView`, 기존 `LogicalViewpoint`)를 추가해 SUD 분해와 요구·FN 할당을 보인다. 기존 `logicalDecompositionView`는 바꾸지 않는다.
6. Registry에 새 정의를 등록한다(`concept-registry-guard`). 새 요구·하위 LC가 K10(OBJ → … → LC) 사슬을 끊지 않고 K15 고아 0인지 확인한다. 같은 판정이 `L2MonitorComponent`와 중복되면 병합하고 이유를 적는다.
7. `check_namespace.py`, `lint.py`, `syside check egas2/model`, IDE 진단을 확인한다. 새 안전 요구가 있으므로 `safety-reviewer`에게 검토를 맡기고 지적을 처리하거나 OI로 올린다.
8. handoff `T22.md`에 "추상화 1회전의 비용과 반복 가능성"(파일 수, 줄 수, 중복 정도, 도구 마찰)을 짧게 쓴다. T24의 평가 재료다. `/close-task`를 실행하고, 그때 `tasks/T23.md`의 "T22 건너뜀" 문장을 고친다.
