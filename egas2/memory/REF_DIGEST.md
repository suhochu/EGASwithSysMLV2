# REF_DIGEST: SPES(2012)와 EGAS v6.0 요약
EGAS 번호는 원문 문단 ID(EGAS_e###)이며 SourceRef로 쓴다. 원문 PDF는 다시 읽지 않는다.

## SPES에서 확인한 규칙
| 주제 | 내용 | 반영 |
|---|---|---|
| 요구사항 뷰포인트 | Context, Goal, Scenario, Solution-oriented(구조·연산·거동) 4종. 절차는 Context → Goal → Scenario → 해결지향 요구(SPES 4.4) | 사용자 순서와 다름 → D-01. SHR·SYSR 구분은 사용자 확장 → D-02 |
| 일관성 규칙 | 컨텍스트 액터 ↔ 시나리오 액터 양방향 일치, 모든 목표는 시나리오 1개 이상이 만족, 모든 시나리오는 목표 1개 이상을 만족, 시나리오에 선·후조건, 요구 속성은 목표 1개 이상으로 추적, 입출력 일관성(Hint 4-1~4-7) | lint 규칙과 viewpoint의 require constraint |
| 목표·시나리오 | 목표 hard/soft, AND/OR 정제, 충돌·기여 관계. 시나리오 main/alternative/exception | 메타데이터 GoalData, ScenarioData |
| 기능 뷰포인트 | user function(UF)은 경계에서 관측되는 동작이며 인터페이스는 컨텍스트의 부분집합. 내부 구성 동작은 WB의 function(FN). 의존은 mode channel (SPES 5.2~5.4) | UF=BB, FN=WB. 모드 개념 1종 |
| BB와 WB 적합성 | WB 함수들의 합성 동작이 BB와 같아야 하고 입출력 매핑표 필요. 시나리오는 BB의 검증 조건 | T15 입출력 매핑표 |
| 논리 뷰포인트 | 논리 컴포넌트는 포트와 채널의 트리. 루트는 기능 BB 경계를 채택. 분해는 비기능 요구(독립성 등) 기준. UF와 LC는 n:m (SPES 6.3~6.6) | T17 루트 = 경계, T18 분해 근거는 독립성·안전 |
| 추상화 계층 | 컴포넌트를 분해하면 각 컴포넌트가 다음 계층의 새 SUD가 되고 같은 산출물 세트가 반복(SPES 3.4.1) | 파일럿은 1계층, 선택 T22 |
| 안전 | 횡단 품질 측면. 컴포넌트마다 fault tree, 실패 모드는 포트에, 전파는 연결을 따름. 품질 요구는 해결지향 요구에 주석(SPES 4.4, 8장) | 메타데이터 주석, C²FT-lite(T19) |
| 실시간 | 제약은 상태·전이에 주석하고 목표로 추적. WCET·jitter·period·priority는 기술 뷰포인트 속성(SPES 9장) | 단계별 ms 예산 제외. FDTI·FRTI·FTTI만 |

## EGAS v6.0에서 확인한 것
- 안전 목표: SZ-01 비의도 가속 ASIL B(e83), SZ-02 가속 부재 QM(e84), SZ-03 비의도 감속 QM(e85), SZ-04 감속 부재 QM(e86). SZ-02~04는 "제어 가능"이라 고려 제외(e88). SZ-01에 대한 감시 개념이 필요하며 허용 시간 내 안전 상태로 전환(e87). 요구는 ASIL B로 구현(e90). S/E/C와 FTTI 값은 없음.
- 안전 요구(e105~e111): SReq-01 센서 합리성 검사(페달), SReq-02 센서 합리성 검사(스로틀, 가솔린 공기 계측 시스템만), SReq-03 ECU가 센서 계통 고장을 합리성으로 검출, SReq-04 타 ECU의 토크 요청을 신호 복합에서 보호, SReq-05 ECU가 액추에이터 오류(스로틀, 연료량)를 합리성으로 검출, SReq-06 ECU에 안전 개념 구현: 과대 구동 토크·비의도 가속을 검출·확정하고 안전 상태로 전환, SReq-07 기능 컨트롤러 감시(L3).
- 3-Level 모니터링(e117~e128): L1 기능(엔진 제어 기능, 부품 감시, 입출력 진단, 반응 제어), L2 기능 감시(L1 기능 소프트웨어의 오류 검출, 허용 토크·가속도와 실제 값 비교), L3 컨트롤러 감시(독립 모니터링 모듈 L3_MM과 기능 컨트롤러의 L3_SW 사이 Q&A). 반응은 기능 컨트롤러와 독립적으로 발동(e127). L1과 L2는 독립 개발로 시스템적 오류가 같은 영향을 주지 않게 함(e101), ECU HW 무결성 확인(e102).
- 수치: Q&A 반복 80 ms 이하(e369), 질문 10개 이상(e340, e383), 토크 감시 검출→반응 시작 벤치마크 예 500 ms(e435), 셧오프 경로 테스트 주행 사이클당 1회(e403)와 엔진 구동은 테스트 성공 후에만 허가(e404), ROM 전체 검사 시동 전 주행 사이클당 1회(e642). 그 밖의 값 대부분은 project specific 또는 calibratable.
- 기본 원칙: 센서→"가정 결함(assumed)" 후 명시적 검출을 거쳐 "확정 결함(confirmed)"으로 분류하고 각각 반응을 정의(e47, e48). 단일·이중·이중(dual)·잠복 오류 구분(e17~e21). 단계적 오류 반응 지향(e46). 엔진 정지는 다른 제어 가능한 반응이 없을 때만 허용(e50). 기능 모니터링은 단순·견고(e43, e53). 낮은 ASIL 기능이 높은 ASIL 기능에 영향 없어야 함(Freedom of Interference, e664).
- 페달·브레이크 합리성(e197~e199): 운전자가 페달로 추진력을 요구하면서 주행 중 서비스 브레이크를 최소 힘으로 밟으면 추진력을 제어 가능한 최대 한계로 감소. 브레이크 신호 입력의 적절한 감시 필요.
- 페달 센서(PVS) 고장 반응(11.1.1, e445~e465): 채널 1·2의 범위 검사 상·하한 초과 시 다른 채널로 limp home과 추가 제한(브레이크 작동·고장 시 최대 값·기울기 제한, 아이들 속도 요구), 두 채널 불일치 시 최소값 선택 limp home, 공급 전압 이탈 시 아이들 속도 요구.
- 시스템 경계(Fig 1, e78): EGAS-System 안에 가속 페달, ECU, 스로틀 밸브. 밖에 CC 레버, 브레이크, 추가 ECU(토크 요청), 추가 센서·부품, 연료 분사·점화.
- 용어: injection cut off(ICO, e34), PVS(e35), TPU(e36), raw signals(e28~e30), SW/HW reset(e31~e33). 표준은 ISO 26262 1판(2011)을 인용(e60).
- 변형(범위 선택, D-05): 가솔린 매니폴드 분사, 가솔린 직분사, 디젤 토크 비교, 디젤 가속도 비교, 가솔린 가속도 비교, A-SaCo(가속도 센서 기반).
